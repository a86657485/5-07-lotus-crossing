### 1.2 登录流程

1. 先选 **班级**（501／502／503／504）。

### 1.3 稳定 studentId

```
studentId = `${classId}|${normalizedName}|${rosterIndex}`
```

| 字段 | 说明 |
| --- | --- |
| `classId` | `"501"`…`"504"` |

## 2. 站序门禁与 taskId

> 出处：**02 §12**（工程接口摘要）。必须使用且仅使用下列 taskId（给学生 UI **不可见**）。

### 2.1 taskId 枚举

| taskId | 站／子任务 | 证据 | 前置 |
| --- | --- | --- | --- |
| （导入微观察，无独立 taskId 或 `intro_e0` 可选） | 开场 | **E0**（不判达标） | 登录后 |
| `s1_order` | S1 行人过街引导台 | 过程／G1·K1 打底 | 导入结束或跳过导入 |
| `s2_rewrite` | S2-A 改写循环图 | **E1**（D1） | `s1_order` 通关 |
| `s2_vs_branch` | S2-B 循环≠分支 | **E2**（D2） | 建议 S2-A 锁定后；同站可顺序强制 A→B→C |
| `s2_kettle` | S2-C 保温壶先问／先做 | **E3**（D3） | 建议 S2-B 完成后 |
| `s3_timing` | S3 路口信号调度台 | **E4**（G2） | S2 整站出口（E1∧E2∧E3 完成） |
| `exam` | 当课分层考核 | **E5** | **S1∧S2∧S3** 当前通过 |

选做空调迁移（E6／B18）可用扩展码 `e6_ac_optional`（见 03 `taskIdMap`）；**不参与开考条件**。

### 2.2 解锁顺序

```
登录 → 导入(E0,可跳过) → s1_order → (S2 先学卡)
      → s2_rewrite → s2_vs_branch → s2_kettle
      → s3_timing → exam（自动开考）
```

- **站序锁死**：S1→S2→S3，不可乱序（02 §2）。
- S2 三子任务 **同站压缩**（E1+E2+E3 同压于 S2）；出口条件：`E1∧E2∧E3` 均完成（首答或支持后均可出口，证据分档）。
- 跳过导入：只推叙事 flag，**不记学习达成**；仍可进 S1。


### 2.4 解锁核验态分支（工程规格｜对齐 02 §7.4）

服务端与客户端须维护每站／子任务的 `gateState ∈ {pre_missing, pre_done_unverified, verified_ready}`。

| 状态 | 判定要点（示例） | UI／对白／法宝 |
| --- | --- | --- |
| `pre_missing` | 前置 `taskId` 未达通关 | 指路缺的前置；法宝不代做 |
| `pre_done_unverified` | 前置动作已发生（如 S3 已 `faultObserved=true`）但未完成核验／换规则／重验 | **禁止**再指「重做前置／再跑故障」；改指「提交／换规则／再运行核对」 |
| `verified_ready` | 核验通过，下一站 `unlocked` | 焦点下一站入口 |

**S3 硬规则**：当 `s3_timing.faultObserved==true` 且（`ruleChanged≠true` 或 `revalidateOk≠true`）时，法宝／焦点／锁定话术 **不得** 再出现「再跑一遍故障」「用原时长重现」类文案。

**重做本关**：学生端提供 `station:reset`（或 UI「重做本关」）→ 重置当前 `taskId` 进度；默认不扣分；法宝整课已用次数不因本关重置而回补；教师「重开本课」才新 `runId`。

桥事件建议增补：`gate:state {taskId, gateState}`；`station:reset {taskId}`。

### 2.3 通关与首次达成去重

| 规则 | 口径 |
| --- | --- |
| 首次达成 | 同一 `studentId` + 同一 `runId`（轮次）+ 同一 `taskId`，**首次**达到通关／锁定成功只记一次主进度与主分相关事件 |
| 支持后完成 | 可另记 `completionKind=supported`；不覆盖 `firstSuccessAt` |
| 服务端去重键 | `dedupeKey = hash(studentId|runId|taskId|eventType|attemptKind)`；推荐 `eventType∈{station_pass, evidence_lock, exam_submit, relic_use, scaffold}` |
| 积分 | 未达标不发主分；站点行走／对白次数**不**单独发掌握分（01／02） |

`runId`：当课一次完整尝试；教师「重开本课」生成新 `runId`；不跨课续答。

## 3. 证据字段与 E1–E5 上报口径

### 3.1 E0–E6 总表（对齐 01 §4.1、02 §1）

| 证据 | 含义 | 触发时机 | 计入达标？ | 主要 payload |
| --- | --- | --- | --- | --- |
| **E0** | 导入微观察：点选「反复等」 | 开场点选／跳过 | **否** | `choiceId`, `skipped` |
| **E1** | 「观察并等待」改写为带回边循环图 | S2-A **首次锁定** | 过程掌握；**考核另计 E5** | 见下「首答／支持后」 |
| **E2** | 选出「再做一遍」意图图／回边 | S2-B 提交 | 同左 | `selectedSide`, `highlightedBackEdge` |
| **E3** | 保温壶：条件／反复／先问或先做 | S2-C 提交 | 同左 | `conditionId`, `repeatStepId`, `timingChoice` |
| **E4** | 时长策略＋理由（路口信号时长） | S3 完成实测→布置→理由→重验 | 最近一次可修订；不替代 E5 | `scenario`, `strategyId`, `reasonId`, `revalidateOk` |
| **E5** | 分层考核整卷 | `exam` 提交 | **是**（只按基础层） | 见 §4 |
| **E6** | 选做空调／生活再认 | 选做／挑战素材 | **否**（不开考条件） | 可选 |

**覆盖核验（不得改）**：G1←E1/E2/E5；G2←E4/E5(+E6)；K1←E0/E1/过程；K2←E1/E3；D1←E1；D2←E2；D3←E3。

### 3.2 站证据字段映射

| 站码 | taskId | 证据 | G/K/D | 记录 |
| --- | --- | --- | --- | --- |
| S1 | `s1_order` | 过程（非 E1–E5 主码） | G1 K1 | 顺序正确＋指出「观察并等待」；可记 `stepsOrder`, `waitingStepId` |
| S2-A | `s2_rewrite` | E1 | D1 K2 G1 | 菱形条件／矩形反复／回边 |
| S2-B | `s2_vs_branch` | E2 | D2 G1 | 循环意图 vs 分支 |
| S2-C | `s2_kettle` | E3 | D3 K2 | 条件／反复／先问先做；**禁「循环体」** |
| S3 | `s3_timing` | E4 | G2 | 故障实测→策略→理由→重验 |
| Q | `exam` | E5 | 全部 | 见 §4 |

### 3.3 首答／支持后／最近／历史

| 口径 | 定义 | 用途 |
| --- | --- | --- |
| **首次（first）** | 该 `taskId`／该题 **第一次锁定或提交** 的对错与作答快照 | E1–E3、基础层达标、主分；**重做不改** |
| **支持后（supported）** | 使用三错支架／法宝提示后再次完成 | 分档展示；可出口；**不冒充首答独立掌握** |
| **最近（latest）** | 最后一次提交 | E4 可修订；大屏「最近成绩」；诊断 |
| **历史（history）** | 追加事件流 | 审计、错因趋势；不加主分 |

过程标签（若实现）：`attemptTag ∈ {first, revise, scaffold_supported, independent_transfer}`（迁移多见于考核／E6）。

### 3.4 通关法宝

| 项 | 规格（出处 02 §7.1） |
| --- | --- |
| 整课配额 | **已锁固定 3**（`relicQuota=3`）；三站各收叙事碎片：斑马线哨／回边箭头／时长旋钮 |
| 可选外观 | 完美首答可加亮 2 片（保温壶贴／对比镜），**不挡开考**、不占求助配额 |

| 扣分 | **不扣积分**；**不计入错误次数**（可记 `relicUsed` 事件） |

### 3.5 三错递进（事件 schema）

对齐 02 §5.7／§7.2：连续失误或点「求助」→ 学生同意后升一级；**不直接给本题概念答案**。

```json
{
  "eventType": "scaffold",
  "studentId": "501|张三|0",
  "runId": "20261101-501-a1",
  "taskId": "s2_rewrite",
  "misconceptionId": "M3",
  "level": 1,
  "levelLabel": "observe|idea|concrete",
  "promptShown": "菱形里要能回答是或否。",
```

### 4.1 题量核对（与 03 一致）

### 4.2 分层与解锁

- 每题带 `tier`: `base`｜`challenge`。
- 挑战层：基础层**本轮已提交（≥1 次）**后自动解锁；**只加分**，不影响达标／奖励。
- 学生端只下发白名单字段（03）：`id, tier, type, stem, prompt, options, cards, rows, interaction, diagramRef, platform, fixedBlocks, blockMeta` 等。
- **不下发**：`answer, accept, analysis, misconceptionMap, goalIds, keyIds, difficultyIds, solo, literacy, teacherNote, …`
- 题数**不写死在前端**；由服务端／`03_questions.json` 下发 `tiers.base.count` 等。

### 4.3 达标／奖励／挑战加分

| 线 | 口径 | 读字段 |
| --- | --- | --- |
| **达标** | 基础层**首答** ≥**13／16**，且 **G1≥3／5**、**G2≥2／3**（向上取整过半） | `passLine=13`；`objectiveMinimumCounts={G1:3,G2:2}` |
| **奖励小游戏** | 与达标**同门槛** | `rewardLine=13` |
| **挑战加分** | 挑战层首次提交 ≥**4／6** | `challenge.passLine=4` |
| K／D | 基础层均有覆盖；**不另设卡人最低线**（老师 2026-11-01） | — |

积分建议（03）：基础达标主分 20；挑战加分 5；同学生同应用同轮次只记一次（去重）。

### 4.4 开考门禁

```
S1_ok ∧ S2_ok ∧ S3_ok  →  服务端自动开考（taskId=exam）
```

| 项 | 规格 |
| --- | --- |
| S2_ok | `s2_rewrite`∧`s2_vs_branch`∧`s2_kettle` 均完成（首答或支持后） |

| 自动开考 | **必做三站齐**后由服务端置 `examOpen=true`；客户端轮询或桥事件 `exam:open` |

## 5. 教师大屏 `/teacher`

### 5.1 访问与安全边界

| 项 | 规格 |
| --- | --- |
| URL | 独立路径 **`/teacher`**（或同源子路径）；**免密码**（校园局域网信任模型） |
| 网络 | 支持局域网跨设备；**禁止写死** `localhost` 为唯一访问方式；用相对路径或部署时注入 `PUBLIC_BASE` |
| 学生端 | **严禁**任何入口、二维码、隐藏手势指向大屏或测试模式 |
| 数据 | 默认只读 `isTest=false`；可开「含测试」开关（默认关） |

### 5.2 布局

1. **顶部全班概览（固定）**  
   - 分母＝正式名单人数（全年级或当前课次配置）；**不随下方筛选变分母**。  
   - 指标建议：已登录数／分母、三站完成率、开考率、基础达标率、挑战加分率、法宝人均使用、缺考／无记录人数（只计数，**不显示催促文案**）。
2. **下方**：图表 + 学生明细；**共用组合筛选**。

### 5.3 组合筛选与排序

筛选维度：

- 班级（501–504，可多选）
- 姓名（搜索）
- 目标 G1／G2（及可选 K／D 诊断，不卡人）
- 证据状态（E1–E5：无／首答对／首答错／支持后／最近）
- 概念支持（三错级别／是否用过支架）
- 首次成绩区间、最近成绩区间

排序：多列升降序（班级、姓名、各站状态、基础首答分、达标、法宝次数…）。

**缺考／无记录**：排在有记录之后；**不计 0 分**（显示「尚无证据」）。

自动刷新：保留当前筛选与排序（刷新后重放 query state）。

## 6. Godot 4 主场景 + Web 流程图桥接

### 6.1 职责边界

### 6.2 桥接事件（要点）

| 事件名 | 方向 | 用途 | payload 要点 |

| `gate:state` | 双向 | 解锁核验三态 | `taskId, gateState` |
| `station:reset` | JS→GD／GD→JS | 重做本关 | `taskId` |
| `station:focus` | JS→GD | 唯一焦点 | `targetId` |
| `flow:open` | GD→JS | 打开流程图面板 | `taskId`（如 `s2_rewrite`） |
| `flow:close` | JS→GD | 面板关闭 | `taskId, reason` |
| `flow:result` | JS→GD | 面板锁定结果 | `taskId, evidenceCode, attemptKind, correct, payload` |
| `evidence:report` | GD→JS | 非面板证据／过程 | 通用 envelope |
| `relic:use` / `relic:sync` | 双向 | 法宝使用与余额 | `count, remaining, taskId` |
| `scaffold:offer` | GD→JS | 请求三错 | `taskId, level, misconceptionId` |
| `exam:pull` | GD→JS | 拉题 | `{tier}` |
| `exam:questions` | JS→GD 或 Web 自绘 | 下发题（建议 Web 自绘考核页） | 白名单字段数组 |
| `exam:submit` | GD→JS 或 Web | 交卷 | answers |
| `exam:open` / `exam:closed` | JS→GD | 开考／教师关考 | `classId, open` |
| `story:replay` | 双向 | 剧情回放 | `fromFrame:1, closable:true` |

02 示意：`openFlowPanel(taskId)` → 提交回写站状态与证据码。
